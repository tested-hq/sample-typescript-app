# sample-typescript-app

Reference repo showing how [tested.dev](https://tested.dev) fits into a real
TypeScript project. Clone it, run `tested diff`, and see the gap.

## What this repo is

- Small, realistic CRUD-style TS app (~10 source files, ~600 LOC)
- Vitest suite that covers happy paths only — so the project sits at ~28%
  line coverage out of the box
- `.tested.yaml` + GitHub Actions workflow already wired
- The uncovered files (`src/auth/tokens.ts`, `src/api/orders.ts`,
  `src/validation/schema.ts`, `src/util/logger.ts`, etc.) are **intentional**
  demo surface — they're what `tested diff` will flag, and what an MCP-driven
  agent should be able to close

## Try it locally

```bash
pnpm install
pnpm test:coverage
node vendor/tested.js diff --base origin/main
```

You'll see a per-file table with uncovered line ranges. Same thing in JSON:

```bash
node vendor/tested.js diff --base origin/main --json
```

> The CLI is checked into `vendor/tested.js` as a build snapshot while
> `@tested/cli` is unpublished. Once it ships to npm, replace the snapshot
> with `pnpm add -D @tested/cli` and call `pnpm exec tested diff`.

## With Claude Code / MCP

1. Copy `.mcp.json` to your Claude Code config (or merge into the existing
   `~/.claude/mcp.json`).
2. Replace the two `/absolute/path/to/...` placeholders with the actual built
   paths on your machine (e.g. `~/projects/tested/tested-hq/mcp/dist/tested-mcp.js`
   and `~/projects/tested/tested-hq/cli/dist/tested.js`).
3. Restart Claude Code so it picks up the new MCP server.
4. Ask: _"Use the coverage tools to close the gap in `src/auth/tokens.ts`."_

You'll see the agent call `get_uncovered_diff` over MCP, read the
ranges, write a test, run it, and re-check.

## Why intentional gaps

The deliberately untested files are the **demo surface** for tested.dev. They
exist so a reviewer can see, in one screen:

- which files have ranges an agent can target
- what the agent sees through MCP
- what the GitHub Actions output looks like in real CI

## CI

`.github/workflows/tested-diff.yml` runs on every PR against `main`:

1. installs deps with pnpm
2. typechecks
3. runs `pnpm test:coverage`
4. runs `tested diff --base "origin/$BASE_REF" --json | tee tested-output.json`
5. prints the human-readable summary for the build log

Until the tested.dev GitHub App ships and starts posting inline PR comments,
the diff output lives in the CI logs.

## Layout

```
src/
├── api/             # createUser / getUser / placeOrder / cancelOrder ...
├── auth/            # session lifecycle + HMAC-signed tokens
├── db/              # generic InMemoryStore
├── util/            # clock + level-filtered logger
└── validation/      # email + zod payload schema
tests/               # happy-path coverage only
vendor/tested.js     # snapshot of @tested/cli (delete when published)
.tested.yaml         # generated by `tested init`
.mcp.json            # MCP wiring (paths are placeholders)
```
